# شرح قاعدة البيانات (PostgreSQL)

## الفكرة العامة

المشروع مبني بـ **Django**. بـ Django ما نكتب جداول SQL بإيدنا. نكتب **Models**، يعني كلاسات Python،
وكل كلاس يصير جدول بالداتابيس. بعدين نشغل:

```
python manage.py makemigrations   # يحوّل الكلاسات لملف تعديلات (migration)
python manage.py migrate          # ينفّذ التعديلات على PostgreSQL ويسوي الجداول
```

نسخة الـ SQL اللي طلعها Django موجودة بملف `docs/schema.sql` إذا الدكتور يريد يشوف الجداول بشكل SQL.

## الجداول (مقسمة حسب أجزاء المشروع)

### 1. المستخدمين

- **User**: جدول واحد لكل المستخدمين. بيه الإيميل الجامعي (الدخول بيه)، الاسم، كلمة السر (مشفرة)،
  و`role` يحدد طالب أو أستاذ أو أدمن.
- **StudentProfile**: معلومات الطالب:
  - `student_number` رقم الطالب
  - `rfid_uid` رقم كارت الجامعة (للحضور)
  - `department` القسم
  - `batch_year` سنة القبول (الدفعة)
  - `current_stage` المرحلة (1-4)
  - `live_photo` الصورة الحية وقت التسجيل
  - `face_embedding` بصمة الوجه: قائمة أرقام (حقل خاص بـ PostgreSQL اسمه ArrayField)
  - `face_consent` موافقة الطالبة على استخدام صورتها
- **TeacherProfile**: الرقم الوظيفي، القسم، اللقب العلمي، الصورة العادية.
- **StageHistory**: سجل الطالب بأي مرحلة كان بكل سنة.

> **ليش جدول User منفصل عن StudentProfile؟** لأن تسجيل الدخول واحد للكل،
> بس المعلومات تختلف بين الطالب والأستاذ. هذا اسمه **علاقة واحد لواحد (One-to-One)**.

### 2. الهيكل الدراسي

- **Department**: الأقسام.
- **AcademicYear**: السنة الدراسية (مثلاً 2025-2026). قيد بالداتابيس يمنع يكون اكثر من سنة "حالية" بنفس الوقت.
- **Subject**: المادة نفسها (الاسم، الرمز، المرحلة).
- **CourseOffering** (**أهم جدول**): يربط **المادة + الأستاذ + السنة + الفصل**.
  الدرجات والحضور والمحتوى والملخصات كلها مربوطة بيه.
- **Enrollment**: منو الطالب المسجل بأي مادة.

> **ليش نحتاج CourseOffering؟** نفس المادة ممكن يدرسها أستاذين، أو نفس الأستاذ يدرسها كل سنة.
> شرط الملخصات ("نفس المادة ونفس الأستاذ") ما يتطبق بدون هذا الجدول.

### 3. محتوى المادة

- **CourseMaterial**: ملف أو رابط يرفعه الأستاذ، وحقل `section` يحدد **نظري** أو **عملي**.
  قيد بالداتابيس يمنع المحتوى يكون بدون ملف وبدون رابط.

### 4. ملخصات الطلاب

- **Summary**:
  - `kind` النوع: ورقي، PDF، يوتيوب، رابط، أخرى
  - `status` الحالة: بانتظار المراجعة، مقبول، مرفوض
  - `reviewed_by` و`reviewed_at` و`rejection_reason` لمراجعة الأستاذ
  - `is_recommended` موصى به من الأستاذ (قيد: لازم يكون مقبول أولاً)
- **SummaryRating**: تقييم من 1 إلى 5 نجوم. قيد يمنع الطالب يقيّم نفس الملخص مرتين، وقيد يمنع رقم خارج 1-5.

**شرط ظهور الملخص** (الدالة `Summary.objects.visible_to(student)`):
1. الملخص **مقبول**.
2. **نفس المادة ونفس الأستاذ** لمادة مسجل بيها الطالب.
3. اللي رفعه من **نفس الدفعة أو دفعة أقدم**، فالدفعات اللاحقة تستفاد.

### 5. الدرجات

- **Assessment**: أي شي عليه درجة (كوز، شهري، عملي، حضور، نهائي...) مع الدرجة القصوى.
  حقل **`is_published`** هو **إظهار/إخفاء الدرجات**، والأستاذ يتحكم بيه.
- **Grade**: درجة الطالب. قيد يمنع درجتين لنفس الطالب بنفس التقييم، وقيد يمنع الدرجة السالبة.
- **ExcelImport**: سجل كل ملف Excel انرفع: كم سطر نجح، كم فشل، وشنو الأخطاء.

**شكل ملف Excel للدرجات:** أول سطر عناوين:

| student_number | score | notes |
|---|---|---|
| S2 | 8 | ممتاز |

النظام يتأكد من كل سطر: الطالب موجود؟ الدرجة رقم؟ أقل من الدرجة القصوى؟ وإذا فشل سطر، يسجل السبب ويكمل بالباقي.

### 6. الحضور

- **LectureSession**: محاضرة بتاريخ ووقت معين، وبيها ملف Excel الحضور ووقت إرساله للأستاذ.
- **AttendanceRecord**: حضور الطالب:
  - `status` حاضر، متأخر، غائب، مجاز
  - `method` كارت RFID أو يدوي
  - `scanned_at` وقت المسح
  - `face_verified` و`face_match_score` نتيجة التحقق بالكاميرا
  - `verification_photo` الصورة وقت الحضور

> الـ ESP32 والحساسات مرحلة ثانية. الجداول جاهزة تستقبل بياناتها
> (رقم الكارت، نتيجة الوجه)، بس جهاز الـ ESP32 نفسه ما انضاف للداتابيس بعد.

### 7. مشاريع التخرج

- **GraduationProject**: الاسم، الخصائص، الأهداف، التحديات، الخلاصة، العمل المستقبلي، الهاردوير، الشكل الخارجي، المشرف.
- **ProjectMember**: أعضاء الفريق، لأن المشروع عادة مجموعة طلاب. فحص يمنع غير طلاب المرحلة الرابعة.
- **ProjectHardwareItem**: قائمة قطع الهاردوير والعدد.
- **ProjectImage**: صور الشكل الخارجي.

### 8. الشات بوت والإشعارات

- **FAQ**: أسئلة وأجوبة الشات بوت. انقلت من `qustion.csv` (909 سؤال).
- **ChatLog**: سجل المحادثات، حتى نعرف شنو الطلاب يسألون.
- **Notification**: إشعارات مثل "ملخصك انقبل".

## أسئلة متوقعة من الدكتور

**ليش الملفات ما تنخزن داخل الداتابيس؟**
الملفات الكبيرة (PDF، صور) تخلي الداتابيس ثقيلة وبطيئة. فتنحفظ بمجلد `media/` والداتابيس تخزن **المسار** بس.

**ليش نخزن بصمة الوجه مو بس الصورة؟**
مقارنة صورتين كل مرة بطيئة. بصمة الوجه قائمة أرقام (مثلاً 128 رقم) تنحسب مرة وحدة وقت التسجيل،
وبعدين وقت الحضور نحسب بصمة الصورة الجديدة ونقيس المسافة بين القائمتين.

**شنو هي الـ Constraints (القيود)؟**
قواعد داخل PostgreSQL نفسها تمنع البيانات الغلط حتى لو صار خطأ بالكود. مثلاً:
- تقييم بالنجوم خارج 1-5
- درجتين لنفس الطالب بنفس الكوز
- حضور مكرر بنفس المحاضرة
- ملخص بدون ملف وبدون رابط

**شنو يعني ForeignKey؟**
عمود يأشر على سطر بجدول ثاني (علاقة). مثلاً `Grade.student` يأشر على الطالب.
`on_delete=PROTECT` يمنع حذف الشي إذا اكو بيانات مرتبطة بيه (مثلاً ما تنحذف مادة عليها درجات)،
و`CASCADE` يحذف المرتبط وياه.

**ليش PostgreSQL؟**
قوية بالقيود والعلاقات، وتدعم أنواع خاصة مثل ArrayField اللي استخدمناه لبصمة الوجه.

## طريقة التشغيل

```
pip install -r requirements.txt
```

سوي داتابيس بـ PostgreSQL (مرة وحدة):

```
CREATE USER bot_user WITH PASSWORD 'bot_pass';
CREATE DATABASE bot_db OWNER bot_user;
\c bot_db
CREATE EXTENSION IF NOT EXISTS vector;   -- pgvector (يحتاج superuser مرة وحدة)
```

بعدين:

```
python manage.py migrate                 # يسوي الجداول
python manage.py load_initial_data       # ينقل الأقسام وأسئلة الشات بوت
python manage.py embed_faqs              # متجهات أسئلة الشات بوت (pgvector، يحتاج sentence-transformers)
python manage.py createsuperuser         # يسوي حساب أدمن
python manage.py runserver
```

افتحي `http://127.0.0.1:8000/admin` وسجلي دخول بحساب الأدمن.

إذا اسم الداتابيس أو كلمة السر مختلفة، تكدرين تغيرينها بمتغيرات البيئة:
`DB_NAME`, `DB_USER`, `DB_PASSWORD`, `DB_HOST`, `DB_PORT`.

## البحث بالمتجهات (pgvector)

pgvector إضافة لـ PostgreSQL تخلي الداتابيس تخزن متجهات (قوائم أرقام) وتلگى أقربها بسرعة.

| الجدول | الحقل | الأبعاد | المسافة | الاستخدام |
|---|---|---|---|---|
| `university_faq` | `embedding` | 768 | cosine | الشات بوت يلگى أقرب سؤال بالمعنى |
| `university_studentprofile` | `face_embedding` | 128 | L2 (إقليدية) | مطابقة الوجه وقت الحضور |

- كل حقل عليه فهرس **HNSW** حتى البحث يبقى سريع حتى لو كثرت البيانات.
- الكود بـ `university/vector_search.py`: `search_faqs(...)` و `find_face_match(...)`.
- `boot2.py` يستخدم pgvector تلقائياً إذا الأسئلة عندها متجهات، وإلا يرجع للبحث القديم بالذاكرة.
- إذا عدلتي سؤال من لوحة الأدمن، متجهه ينحسب من جديد تلقائياً.
- إذا غيرتي موديل النصوص: `python manage.py embed_faqs --all`

مثال:

```python
from university.vector_search import search_faqs
for faq in search_faqs("شكد القسط؟", k=5):
    print(round(faq.distance, 3), faq.question)
```
