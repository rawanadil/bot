# شرح تنفيذ المشروع (الواجهات)

هذا الملف يشرح الصفحات اللي انبنت فوق قاعدة البيانات. شرح الجداول نفسها موجود بـ `docs/DATABASE_AR.md`.

> الـ ESP32 والحساسات (RFID، الكاميرا عند الباب، DHT11، IR) **مرحلة ثانية**.
> هسه الأستاذ يسجل الحضور يدوياً، والجداول جاهزة تستقبل بيانات الكارت والوجه.

---

## تشغيل المشروع بسرعة (للعرض)

```
pip install -r requirements.txt
python manage.py migrate
python manage.py create_demo_data
python manage.py runserver
```

افتحي `http://127.0.0.1:8000`. كلمة السر لكل الحسابات التجريبية: `demo12345`

| الحساب | الدور | شنو تشوفين بيه |
|---|---|---|
| `student1@uni.edu` | طالبة مرحلة أولى | الداشبورد، المواد، الدرجات، الحضور، الملخصات |
| `student4@uni.edu` | طالبة مرحلة رابعة | خانة مشروع التخرج |
| `teacher@uni.edu` | أستاذ | رفع المحتوى، مراجعة الملخصات، الدرجات، الحضور، المشاريع |
| `admin@uni.edu` | أدمن | لوحة التحكم `/admin` (إضافة مواد، أساتذة، سنوات دراسية) |

## الصفحات حسب أجزاء المشروع

### أولاً: ما قبل التسجيل
| الرابط | الصفحة |
|---|---|
| `/` | الصفحة الرئيسية: أزرار الشات بوت، بحث بالأسئلة الشائعة (909 سؤال من `qustion.csv`)، والأقسام |
| `/chat` و `/pas` | الشات بوت (نفس الكود القديم، ما تغير) |

### ثانياً: التسجيل
| الرابط | الصفحة |
|---|---|
| `/register/` | إنشاء حساب: الاسم، الإيميل الجامعي، رقم الطالبة، القسم، المرحلة، سنة القبول، كلمة السر، **والصورة الحية من الكاميرا** |
| `/login/` | تسجيل الدخول بالإيميل |
| `/verify/...` | رابط تأكيد الإيميل الجامعي (ينرسل بالإيميل) |

**شلون تشتغل الصورة الحية؟**
1. المتصفح يشغل الكاميرا (`getUserMedia`).
2. الطالبة تضغط "التقاط"، والصورة تتحول لنص (base64) وتنحط بحقل مخفي.
3. السيرفر يحولها لملف JPG ويخزنها بـ `media/students/live_photos/`.
4. إذا مكتبة `face_recognition` منصبة، يحسب **بصمة الوجه** ويخزنها بالداتابيس.

ما ينفع ترفع صورة قديمة من الجهاز. لازم تنلتقط من الكاميرا وقت التسجيل.

**بعد التسجيل:** الطالبة تنسجل **تلقائياً** بكل مواد قسمها ومرحلتها بالسنة الحالية (الدالة `auto_enroll` بملف `services.py`).

**الإيميل الجامعي:** إذا تحطين متغير البيئة `UNIVERSITY_EMAIL_DOMAIN=uni.edu.iq`، التسجيل يقبل بس الإيميلات اللي تنتهي بهذا الدومين.

### ثالثاً: داشبورد الطالبة (`/dashboard/`)
- **موادي**: كارت لكل مادة بيه اسم الأستاذ ونسبة الحضور (شريط أخضر) وعدد الغيابات.
- **أنشطتي ودرجاتي**: الدرجات مقسمة حسب النوع (كوز، شهري، عملي...).
- تظهر **بس الدرجات اللي الأستاذ ضغط عليها "إظهار"** (حقل `is_published`).
- الإشعارات الجديدة.

### رابعاً: صفحة المادة (`/subjects/<رقم>/`)
ثلاث خانات (تبويبات):
1. **النظري**: ملفات وروابط الأستاذ للنظري.
2. **العملي**: ملفات وروابط الأستاذ للعملي (تختفي إذا المادة ما بيها عملي).
3. **ملخصات الطلاب**:
   - تظهر بس الملخصات **المقبولة** لنفس **المادة والأستاذ** ومن **نفس الدفعة أو الدفعات الأقدم**.
   - الموصى بيها من الأستاذ تطلع أول، وعليها علامة.
   - تقييم بالنجوم (1-5). الطالبة ما تكدر تقيم ملخصها، وكل طالبة تقيم مرة وحدة (إذا ضغطت مرة ثانية يتعدل تقييمها).
   - زر **رفع ملخص**: PDF، صور ملخص ورقي، فيديو YouTube، رابط، أو مصدر آخر. يروح للأستاذ بحالة "بانتظار المراجعة".
   - خانة "ملخصاتي": تشوف بيها ملخصاتها المعلقة أو المرفوضة مع سبب الرفض.

### خامساً: مشروع التخرج (`/project/`)
- يظهر **بس لطالبات المرحلة الرابعة**. غيرهن يرجعن للداشبورد برسالة.
- الحقول: الاسم، المشرف، الخصائص، الأهداف، التحديات، الخلاصة، العمل المستقبلي، الهاردوير، الشكل الخارجي.
- إضافة **أعضاء الفريق** برقم الطالبة (لازم تكون مرحلة رابعة وما عندها مشروع ثاني).
- إضافة **قطع الهاردوير** والعدد، و**صور الشكل الخارجي**.
- زر **إرسال للمشرف**، والمشرف يقبل المشروع أو يرجعه للتعديل.

### واجهة الأستاذ (`/teacher/`)
| التبويب | شنو يسوي |
|---|---|
| المحتوى | يرفع ملف أو رابط ويحدد نظري أو عملي |
| ملخصات الطلاب | **موافقة** أو **رفض مع السبب**، و**تحديد كموصى به** |
| الدرجات | يسوي تقييم (كوز، شهري...)، يكتب الدرجات يدوياً، أو **يرفع ملف Excel**، وزر **إظهار/إخفاء** |
| الحضور | يسوي محاضرة، يسجل الحضور (حاضر، متأخر، غائب، مجاز)، و**يرسل ملف Excel لإيميله** |
| مشاريع التخرج | يشوف المشاريع اللي يشرف عليها، ويقبلها أو يرجعها |

**ملف Excel للدرجات:**
- زر "تنزيل ملف جاهز بأسماء الطلاب" ينزل ملف بيه أرقام الطلاب.
- الأستاذ يملي عمود `score` ويرفعه.
- النظام يتأكد من كل سطر (الطالب موجود؟ الدرجة رقم؟ ضمن الحد؟) ويكول كم سطر نجح وكم فشل وليش.

**الإشعارات:** تنرسل تلقائياً، مثلاً:
- الطالبة: "انقبل ملخصك"، "انرفض ملخصك"، "نزلت درجات الشهري الأول"
- الأستاذ: "ملخص جديد بانتظار المراجعة"، "مشروع تخرج جديد للمراجعة"

## الحماية والصلاحيات (سؤال متوقع من الدكتور)
- **الطالبة** تفتح بس المواد المسجلة بيها. أي مادة ثانية تطلعلها "Not Found".
- **الأستاذ** يشوف ويعدل بس المواد اللي هو يدرسها.
- الطالبة ما تكدر تفتح صفحات الأستاذ، والعكس.
- كل الفورمات محمية بـ **CSRF token** (يمنع إرسال فورم من موقع ثاني).
- كلمات السر مشفرة (hash).
- الملفات المرفوعة تتأكد من نوعها (PDF لازم ينتهي بـ .pdf، Excel لازم .xlsx).

## الإيميل
- بالتطوير، الإيميلات (رابط التأكيد، ملف الحضور) **تنطبع بالـ terminal** بدل ما تنرسل.
- للإرسال الحقيقي حطي متغيرات البيئة: `EMAIL_HOST`, `EMAIL_PORT`, `EMAIL_HOST_USER`, `EMAIL_HOST_PASSWORD`.
  - مثلاً لـ Gmail: `EMAIL_HOST=smtp.gmail.com` مع App Password.

## بصمة الوجه (اختياري)
مكتبة `face_recognition` تحتاج `dlib` وتنصيبها ثقيل، فخليتها اختيارية:

```
pip install face_recognition
python manage.py compute_embeddings
```

الأمر الثاني يحسب البصمة لكل الطالبات اللي سجلن قبل تنصيب المكتبة.

## الخطوة الجاية (المرحلة الثانية)
- رابط API يستقبل من ESP32 رقم الكارت والصورة، ويقارن البصمة بالدالة `face_distance`، ويسجل الحضور تلقائياً.
- عرض الحرارة والرطوبة والترحيب على الشاشة الذكية.
